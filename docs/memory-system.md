# Memory and evidence

Eight categories distinguish IDEA, INTEREST, GOAL, TASK, COMMITMENT, REMINDER, PREFERENCE and CONTEXT. Common fields live in normalized memories; goal/task/idea subtype tables retain relational identity. UUID sourceId links to the user message. USER_STATEMENT records are structured interpretations of what the user said, with extraction confidence, status, timestamps and optional deadline. Users can edit or delete them.

`MemoryExtractor` is independent of routes. Without an enabled provider, explicit wording is classified by deterministic rules. With an enabled provider, output is parsed through the same Zod schema; malformed JSON, transport errors and timeouts fall back to rules. Provider instructions prohibit converting ideas to goals or questions to intentions. Relative dates are left unresolved by the local fallback and the user is told to set an exact deadline. AI extraction is not guaranteed correct; inspect/edit controls remain available.

For personal recall questions, conversation retrieval supplies bounded sessions and memories plus current context. Yesterday and last week use server-local calendar boundaries. `ConversationResponder` handles normal conversation using recent messages and general knowledge; only recall requests include the activity evidence. It is instructed to use supplied evidence for claims about the user's history, label uncertainty, and never invent work. The local summary for recall states observed apps and recorded statements and never calls inferred progress a fact. Ordinary messages in local mode explain that AI is disconnected instead of responding with an unrelated activity report.

AI configuration and consent are separate: having an API key/model configured does not enable evidence sharing. `/api/v1/ai/status` reports configuration and opt-in status. `/api/v1/ai/test` sends only a synthetic greeting and reports sanitized errors for connectivity, authentication, model/endpoint availability, rate limits or malformed output. Neither arbitrary upstream error bodies nor credentials are returned to the client. The chat response reports generation and extraction status independently so successful extraction cannot masquerade as successful conversation.

AI insights are separate rows with INFERENCE, confidence, evidence references and timestamps. Historical lexical matches may suggest unfinished work. No automatic abandonment/completion assertion is made; active/inactive/stale/possibly_abandoned/completed/archived are editable statuses. Missing activity is explicitly not proof of abandonment.

A direct “don't remind me” disables all reminders immediately as the conservative MVP interpretation of ambiguous “this”. The response states that scope and tells the user how to re-enable them. This does not silently guess which goal the user meant.
